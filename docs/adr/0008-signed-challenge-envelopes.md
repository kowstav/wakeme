# 0008 — Published challenges are signed and verified on the phone

- Status: Accepted (2026-10-19)

## Decision

- Publishing a challenge revision signs canonical JSON with ES256 (P-256, SHA-256, DER).
  The envelope carries the payload bytes, digest, key id and revision id.
- Phones verify digest, signature (against keys pinned from `/v1/config`) and revision id
  before installing a challenge for offline use, then parse the exact signed bytes.
- A signature detects tampering; content safety is enforced earlier by the server validator.

## Verification

`packages/policy-fixtures/fixtures/signed-envelopes.json` (generated by the server's own
`signEnvelope` with a throwaway key) is verified by the server tests, Android `:core`
(`EnvelopeParityTest`) and iOS `WakeMeCore` (`testSignedEnvelopes`) — 7 cases each.
