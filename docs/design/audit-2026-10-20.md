Phase 1 of the premium native design pass. Sources are the code at `7b50acf` (branch
`codex/android-challenge-lifecycle`) plus the existing CI screenshot review log ([README](README.md) §6).

**Evidence limits.** This machine has no Android SDK (the configured path no longer exists), about
1 GB free RAM and no macOS, so nothing native could be built, rendered or run here. Findings come from
reading both apps' source, the design contract and the screenshot log. They are **not** visual

## What is already good (keep)

- Literal status copy on both platforms ("Sent · no confirmation from their phone yet",
  "Challenge completed (not proof they're awake)"). It is better than most shipping apps.
- Recipient-owned permissions are explained where they matter; dialogs say who is told and until when.
- Light-mode semantic colours already share OKLCH lightness ≈ 0.50, so no status colour shouts
  louder than another; the yellow-as-fill / `accentText` rule fixed real AA failures (run 13).
- Android alarm and challenge escape controls sit outside scrolling content (Codex continuation).
- Adaptive Android layouts (rail, list-detail, 640 dp readable width) and iOS native `List`/`Form`.

## Findings

| A1 | P0 | Wake challenge, practice | iOS `ChallengeRunnerView.swift` | The escape button and "simple check-in" scroll with the challenge. | A2 | P0 | Every form with text fields; chips; steppers | Theme/tokens both apps | The only outline colour (`border`, 1.29:1) is also Material's `outline`, so **text-field boundaries, unselected chips and step buttons fail WCAG 1.4.11 (3:1)**. iOS answer fields use `surfaceSunken` on `surface` (1.06:1). | People with low vision can find the field to type into. | S | Add an `outline` role ≥ 3:1 on every surface; keep `border` for decorative separators only. |
| A3 | P1 | All status changes | Both apps | Status changes (delivery pill, "Not quite…", readiness) are **not announced** to TalkBack/VoiceOver; no live regions or announcements anywhere. | Screen-reader users learn that their quack reached the phone, or that an answer was wrong. | S | Polite live region on Android (`liveRegion`), `AccessibilityNotification.Announcement` / `.accessibilityAddTraits(.updatesFrequently)` on iOS. |

state-change motion. Nothing in alarm, SOS or escape flows is animated, which is correct and must stay so.

## Rejected for this product (with reasons)

| Candidate | Decision | Why |
|---|---|---|
| Card → detail **shared element** on Android | Modified: tuned shared-axis transition instead | Navigation 3 1.2 supports a `SharedTransitionScope`, but list-detail scenes swap between one and two panes; without an emulator to verify the pane changes and predictive back, a shared-bounds transition is too risky. iOS uses the native zoom navigation transition, which the system manages. |
| Material 3 Expressive `MotionScheme.expressive()` | Rejected for now | In the pinned Material3 1.4.0 the standard/expressive factories are internal (`expressive$material3`). Own spring tokens give the same control without experimental APIs. |
| Liquid Glass / heavy materials on content | Rejected | Doc 03 §2: "premium ≠ glass everywhere". System bars already adopt iOS 26 materials. Content stays on opaque, legible surfaces. |
| Particles, confetti, looping idle animations | Rejected | Battery, distraction, and "repeated bouncing" rule. One-shot success only. |
| Gradients on components | Rejected | Flat tonal fills read better at a glance and in high contrast. |
| Animated alarm screen | Rejected | Alarm/SOS/escape must be instant and still (doc 03 §4B, CLAUDE.md). |
| One-tap quack from the Friends list | Rejected | Doc 03 §4A: preview and send are separate; a list tap must not send by accident. Launcher/widget quick actions already exist with explicit routing. |
| Rounded custom typeface (e.g. bundled Nunito) | Rejected | Native system fonts carry Dynamic Type, language coverage and platform feel; a bundled font would differ between platforms. Personality comes from weight, size and the duck. |
